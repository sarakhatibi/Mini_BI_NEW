# Mini BI Analytics Platform

یک ابزار تحلیل داده برای مدیران غیرفنی: یک فایل Excel/CSV فروش را بارگذاری می‌کنید و
سیستم داده را پاک‌سازی می‌کند، کیفیت آن را می‌سنجد، شاخص‌های کلیدی و نمودارهای مناسب
همان داده را می‌سازد و در پایان چند جمله تصمیم‌ساز به زبان فارسی ارائه می‌دهد.

مسیر کاربر: **Upload → Analysis → Decision**

## نصب و اجرا

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
streamlit run app.py
```

اپ روی <http://localhost:8501> بالا می‌آید. برای دیدن سریع خروجی، دکمه «نمایش با داده نمونه»
فایل `data/Test_Dataset.xlsx` را تحلیل می‌کند.

اجرای تست‌ها و بررسی سبک کد:

```bash
python3 -m pytest -q
python3 -m flake8 .
```

## معماری

```
app.py                     رابط کاربری Streamlit (آپلود، فیلتر، تب‌ها، خروجی)
components/dashboard.py    نمایش KPI، بینش و نمودار
services/
  data_loader.py           خواندن CSV/Excel (تشخیص encoding و جداکننده، انتخاب شیت)
  text_utils.py            یکسان‌سازی متن فارسی/عربی، ارقام، نیم‌فاصله
  numeric_utils.py         تبدیل امن عدد متنی («1,250.50»، «18450 USD»، «10%»)
  date_utils.py            تشخیص و تبدیل تاریخ میلادی و شمسی
  data_cleaner.py          پاک‌سازی قابل ردیابی + گزارش هر تصمیم
  semantic_profiler.py     تشخیص نقش معنایی ستون‌ها (مبلغ، تاریخ، مشتری، وضعیت، ...)
  data_analyzer.py         ساختار داده + امتیاز کیفیت و فهرست مشکلات
  kpi_engine.py            محاسبه KPI بر اساس پروفایل معنایی
  chart_engine.py          انتخاب نمودار مناسب بر اساس پروفایل
  insight_engine.py        تولید بینش مدیریتی فارسی
  pipeline.py              زنجیره کامل: clean → profile → analyze → quality
tests/                     تست‌های بخش‌های حساس
```

جریان داده:

```
فایل خام → load_file → clean_dataset → profile_dataset → analyze_dataset/assess_quality
                                     → calculate_kpis / create_charts / generate_insights
```

### چرا «پروفایل معنایی»؟

KPIها Hard Code نشده‌اند. `semantic_profiler` با ترکیب نام ستون و آمار مقادیر تصمیم می‌گیرد
که هر ستون چه نقشی دارد (measure مالی، درصد، تاریخ، شناسه، دسته‌بندی، متن آزاد) و بقیه ماژول‌ها
فقط از این نقش‌ها استفاده می‌کنند. در نتیجه روی دیتاست ناشناس هم خروجی معنادار تولید می‌شود و
اگر ستونی وجود نداشته باشد، شاخص مربوط به آن ساخته نمی‌شود.

### پاک‌سازی قابل ردیابی

`clean_dataset` هیچ رکوردی را جز ردیف‌های کاملاً تکراری حذف نمی‌کند و هر تغییر را در
`CleaningResult.actions` ثبت می‌کند؛ همین جدول در تب «کیفیت داده» به کاربر نشان داده می‌شود.
شناسه‌هایی مثل `ORD-14040001` و `P-104` عمداً به عدد تبدیل نمی‌شوند.

موارد پوشش‌داده‌شده: مقادیر خالی، رکورد و شناسه تکراری، ناسازگاری نوع داده، عدد ذخیره‌شده
به‌صورت متن، درصد و واحد چسبیده به عدد، تاریخ شمسی و میلادی هم‌زمان، نیم‌فاصله و فاصله اضافه،
املای متفاوت یک مقدار، مقادیر منفی/پرت و ستون‌های بی‌اطلاعات.

## قابلیت‌های رابط کاربری

- تب **داشبورد**: شاخص‌ها، بینش‌های مدیریتی و نمودارها (روند ماهانه، Top-N، سهم دونات، وضعیت، توزیع)
- تب **کیفیت داده**: امتیاز ۰ تا ۱۰۰، فهرست مشکلات با شدت، و گزارش تصمیم‌های پاک‌سازی
- تب **نقشه ستون‌ها**: برداشت سیستم از معنی هر ستون
- تب **داده‌ها**: جستجو، مرتب‌سازی، صفحه‌بندی و دانلود CSV پاک‌شده و گزارش پاک‌سازی
- فیلترهای کناری: دسته‌بندی، بازه تاریخ و بازه عددی + بازنشانی

## Database Schema

پروژه پایگاه داده ندارد؛ داده در حافظه پردازش می‌شود و خروجی به‌صورت CSV قابل دانلود است.
